# NetApp Volume Utility

Утилита администрирования томов/лунов на кластерах NetApp (C400, C800) через SSH-обёртку
над CLI. Заменяет длинные ручные команды простыми операциями: создать Volume,
создать LUN, примапить LUN, показать луны.

Причина существования: веб-интерфейс NetApp неудобен, саппорт сам рекомендует CLI,
но строки команд длинные и подвержены ошибкам. Утилита фиксирует «строгие» параметры
(SVM, аггрегаты, QoS-политики, флаги) и не даёт ошибиться.

## Статус
**Минимально запускаемая версия.** `src/` написан: логин без сохранения кредов,
выбор кластера C400/C800 и цели PROD/TEST, backend Real(paramiko)/Fake(эмулятор),
4 вкладки + живая SSH-консоль, валидация имён, локализация UA/RU/EN,
тёмная/светлая тема. Строгий слой (svm0, аггрегаты, QoS, флаги, квирк +3%)
собирается только из `app_config.py`, который зеркалит `config/clusters.md`.
Smoke-тест и живой прогон окна (на Fake-бэкенде) проходят без ошибок;
Real-бэкенд на реальном кластере пока не проверен.

Аудит QA v0.1.7 (2026-08-16): 24 PASS / 1 FAIL critical / 5 NOTE. Критический баг
Real-бэкенда (ложный `success=False` на медленной СХД) **исправлен в v0.1.8** -
см. ниже. Живая проверка Real-режима требует реальных адресов кластеров
(в конфиге пока заглушки `0.0.0.0`).

Расхождение `-ostype` (windows vs windows_gpt) **закрыто** (2026-08-16): ostype
теперь per-cluster, как в исходных рабочих скриптах - C400: `windows_gpt`/`linux`,
C800: `windows`/`linux`. Адреса кластеров в конфиге - заглушки `0.0.0.0`
(реальные подставляются оператором на месте).

**Ответ СХД ловится как в оригинальных PS1, но с живым выводом** (2026-08-16):
`volume create` ждёт в выводе маркер `Successful`, `lun create` - `Created a LUN
of size` (таймаут 30 с, как `$Stream.expect` в эталонах). `lun mapping create`
и `lun show` - без фильтра, как в оригинале. При этом сырой вывод (эхо команды +
ответ + промпт) по-прежнему показывается в консоли как есть, а факт успеха/ошибки
дополнительно подсвечивается цветом - зелёное «Успешно» / красное «Ошибка».

**B01 (фикс v0.1.8, по отчёту QA-024 critical):** при ожидании маркера бэкенд
больше НЕ выходит по «1 с тишины» - ждёт маркер до дедлайна 30 с, как эталон
(раньше на медленной СХД команда реально выполнялась, но приложение показывало
ложный `success=False` через ~1 с). Эвристика тишины осталась только для
свободного вывода (`lun mapping create` / `lun show` / живая консоль).

**Чекбокс «Повторить имя и размер» (Volume → LUN, v0.1.8, фича-реквест FR01):**
на вкладке LUN, **по умолчанию отмечен** (у клиента ~99% совпадений имени тома
и LUN). При отмеченном - имя, размер и единица переносятся с вкладки Volume;
при снятом - вкладка LUN полностью независима. ⚠️ **Квирк +3% НЕ переносится**:
на LUN уходит размер КАК ВВЕДЁН, квирк применяется фоном ТОЛЬКО к команде
`volume create` (пример: желаемый 100GB → `volume create -size 103GB`, LUN = 100GB).
Состояние чекбокса сохраняется в settings.json.

**Mapping (M01, сознательное расхождение с оригиналом):** реализация шлёт
LUN→`-lun`, Volume→`-volume` - семантически верно для ONTAP. В оригинальных PS1
поля перепутаны (имя Volume уходит в `-lun` и наоборот) - это баг оригинала,
сознательно не повторяется (решение оператора, QA-015).
**Вкладка «Примапить LUN» (v0.1.10):** поля идут в порядке **Volume → LUN →
igroup → LUN ID** (Volume первым - логика «LUN живёт внутри тома»). Имена
Volume/LUN автоматически подтягиваются с вкладок «Создать Volume» и «Создать
LUN» при открытии вкладки Mapping. Поле igroup - **редактируемый комбо**: список
тянется с СХД командой `igroup show -vserver svm0 -fields igroup` (доки ONTAP
9.19.1; кнопка «Обновить igroup» + автозагрузка при первом показе вкладки),
либо имя можно вписать руками.

QoS в UI: по умолчанию стоит `no-qos`, выпадающий список заблокирован; рядом
чекбокс «разрешить выбирать» (по умолчанию снят) снимает блокировку. Набор политик
и подсказки - дословно из исходных скриптов (`_reference/*.ps1`). QA-028
(2026-08-16): оператор подтвердил поведение - на обеих железках по умолчанию
`no-qos`, остальные политики выбираются только после снятия блокировки; все
5 политик остаются доступными (задизейбленный bronze/silver из оригинала
не повторяем).

Темы: на окне входа рядом с языком выбирается «Светлая» (дефолт Qt) или «Тёмная»
(полная QSS: окна, инпуты, комбо, чекбоксы, кнопки, вкладки, консоль, таблицы,
скроллбары). Выбор применяется сразу (превью). В тёмной теме стрелки
выпадающих списков - собственные светлые (видны на тёмном фоне), в светлой
теме - системные стрелки Qt. Иконка приложения - `src/assets/app_icon.png` (ставится на окно входа, главное окно и в панель задач).
На окне входа внизу - между выбором режима (SSH/Fake) и кнопками - показывается
логотип `src/assets/login_logo.png` (пропорционально сжат до ширины 300px, по центру).

Последние выбранные **язык и тема запоминаются** (2026-08-16): при успешном входе
они пишутся в `~/.netapp_volume_utility/settings.json` (домашний каталог, вне
проекта) и восстанавливаются при следующем старте. Учётные данные туда не попадают
и нигде не сохраняются - только безобидные UI-предпочтения (там же хранится
состояние чекбокса FR01, там же - переопределения адресов кластеров
(hosts: {кластер: {PROD|TEST: адрес}}), адрес не вшит в exe.

**Клиентская сборка (v0.1.16, 2026-08-17):** окно входа без выбора «Цель»/«Режим» -
жёстко PROD + реальный SSH; адрес СХД вводится на окне входа и сохраняется
в settings.json. exe собран с иконкой app_icon.ico.

**Размер тома/LUN - строго по офиц. докам ONTAP, не по оригинальным PS1**
(2026-08-16, уточнение оператора: в этом кейсе оригинал НЕ эталон; правила
одинаковы для обоих кластеров). Доки (docs.netapp.com, v9.19.1):
`volume create -size {<integer>[KB|MB|GB|TB|PB]}` - только целое + единица,
минимум FlexVol 20 MB; `lun create -size` - целое число байт с суффиксом-
множителем (c/w/B/k/M/G/T). Дробные, ноль и отрицательные отклоняются ещё
до отправки на СХД. Единицы - GB/TB, как в исходных скриптах; минимум 20 MB
при этом удовлетворяется автоматически (1 GB > 20 MB). Квирк +3% для volume
округлён вверх до целого - `ceil(VSize * 1.03)`: `100` → `-size 103GB`,
`33` → `-size 34GB` (гарантия «как минимум +3%» при целочисленном `-size`;
раньше было `33.99GB` - так печатает float PS1, но это нарушает доки).

**Имена Volume/LUN - строго по докам ONTAP + SPEC.md (2026-08-16, решение
оператора по QA-022):** имя начинается с латинской буквы (a-z/A-Z), далее -
латинские буквы/цифры/подчёркивание; без пробелов и служебных символов; максимум
203 символа. Источник - KB NetApp «Can a NetApp volume name contain a hyphen or
dash» (ONTAP 9): volume names contain only alphanumeric characters and underscores,
must start with a letter. Дефисы и кириллица тоже запрещены (SPEC.md). Доки по LUN
(lun-create) разрешают также `-`, `{`, `}`, `.` (макс. 255) - по SPEC.md и
решению оператора они запрещены и для LUN: сознательное расхождение с доками
в пользу единого строгого правила (`^[A-Za-z][A-Za-z0-9_]{2,202}$`).

## Задуманная функциональность (ТЗ)
- Логин при старте (host / user / password + выбор кластера C400/C800 + цель PROD/TEST),
  учётные данные только в памяти процесса, никуда не пишутся.
- Вкладки: Create Volume / Create LUN / Map LUN / Show; снизу - живая SSH-консоль.
- Строгий слой параметров из конфига (UI не собирает командные строки руками).
- Валидация имён (по докам ONTAP): начинается с латинской буквы, далее - латинские
  буквы/цифры/подчёркивание, без пробелов и спецсимволов, максимум 203 символа;
  размер - целое положительное число.
- Backend: `Real` (paramiko, PROD) и `Fake` (эмулятор ONTAP, TEST).
- Локализация UA / RU / EN; тёмная/светлая тема (последний выбор запоминается).

## Запуск
```
.venv\Scripts\python.exe src\main.py
```
При старте - окно логина: язык (UA/RU/EN), тема (светлая/тёмная),
пользователь/пароль, кластер (C400/C800), адрес СХД (сохраняется в
settings.json; меняется без пересборки exe). В клиентской сборке выбор
цели и режима скрыт - жёстко PROD + реальный SSH (RealBackend);
в исходниках вернуть выбор можно, раскомментировав строки в login_dialog.py.
Учётные данные нигде не сохраняются, живут только в открытом SSH-соединении.
PySide6 обязателен; paramiko нужен для Real-режима.

## Структура
- `_reference/` - исходные рабочие скрипты C400/C800 (не трогать, эталон поведения)
- `config/`     - строгие параметры кластеров (C400/C800)
- `docs/`       - спецификация операций и параметров
- `src/`        - код (app_config, validation, ontap_commands, session, i18n, theme,
  settings, backend/, ui/, main.py)
- `state/`      - статус-доски агентов (developer/qa)
- `tests/`      - отчёты QA (qa_report, report.json)
- `_TEMP/`      - черновики и временный хлам (не для продакшена)


## Сборка standalone exe

- Точка входа: `src/build_main.py` (обёртка над `main.py`).
- Сборка встроенным инструментом `compile_exe` (PyInstaller из venv ai_ui, Python 3.12).
  Требование: в окружении сборки установлен `paramiko` (5.0.0 + cryptography + cffi) -
  иначе exe соберётся без SSH-поддержки.
- Ассеты (логотип входа `login_logo.png`, иконка `app_icon.png`) вшиты в код через
  `src/assets_data.py` (base64) - exe автономен, не зависит от файлов на диске.
- Иконка exe - `app_icon.ico` (вшивается в ресурсы готового exe после
  сборки, не через PyInstaller `--icon`).
- ВАЖНО: не собирать exe с подтягиванием paramiko из `.venv` проекта -
  тот собран под Python 3.14, а окружение сборки 3.12 (ABI-несовместимость,
  падение `_cffi_backend`).
